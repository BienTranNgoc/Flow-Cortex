# Constitution — the non-negotiable planning principles (stable IDs, append-only)

On-demand reference (not always-loaded). `/explore` pulls the lens each ID names; `/proposal`'s Debt & Coverage Audit emits the matching tag; `/verify` reports every ID as **pass / violation / N/A — reason**. `scripts/check-req-traceability.mjs --constitution` warns when a change's artifacts mention none of an ID. IDs are never renumbered or deleted — retire with `(retired YYYY-MM-DD: reason)` so old specs still resolve.

| ID | Principle | Trigger | Lens / source | Proposal tag | Verify proves |
|---|---|---|---|---|---|
| **C-01** | Business rules are *generated*, not recalled — Rule / Example / Question cards + the unwanted-behaviour sweep, every non-happy trigger gets an `IF … THEN …` line naming status, message, next action | behaviour a domain expert has an opinion about | `business-rule-coverage-checklist.md` | `[RULE]` | each `#### Scenario:` with a concrete rule is satisfied by code, not just addressed |
| **C-02** | Every plan classifies itself one-way / two-way door; one-way enumerates consumers (not inferred) and sequences persisted-shape change expand → migrate → contract with migration-vs-deploy order stated | any plan | `engineering-judgment-checklist.md` | `[DOOR]` | door marker present; consumer list matches GitNexus depth-2 |
| **C-03** | Lifecycle state names its invariant and its enforcement layer (DB constraint / atomic write — an application `if` is not enforcement); the four concurrency questions are walked out loud (same user two tabs, two actors, check-then-act, late arrival) | writes status / money / quota / slot / entitlement | `concurrency-state-checklist.md` | `[RACE]` | invariant enforced below the app layer |
| **C-04** | User-reachable behaviour ships with a runtime off switch (backend *and* view) in the project's existing toggle mechanism; "revert and redeploy" is not a recovery path | user-reachable feature | `rollout-safety-checklist.md` | `[SWITCH]` | switch exists, is registered, and the write path honours it |
| **C-05** | Migrations run in one transaction per set, filenames carry HH:MM:SS and sort after the newest committed one, `down()` is honest, and the CI apply order is stated | adds a migration / touches existing rows | `migration-safety-checklist.md` | — (verify dimension) | artifacts and diff agree on the four migration facts |
| **C-06** | Security boundaries parse every value crossing them with a schema (type derived from schema); the lethal-trifecta split holds (private data + untrusted content + outbound channel never in one flow) | auth / authz / payment / PII / upload / webhook / external API / deserialization | `security-checklist.md`, CLAUDE.md §8, §13 | — | boundary parse present; no trifecta flow |
| **C-07** | Hot paths carry a stated budget (p95 latency / INP / query count) and the plan says how it is measured; observability names what is emitted and what alerts | new endpoint, list/feed query, render-critical UI, background job | `performance-checklist.md`, `observability-checklist.md` | `[NFR]` | budget stated and a measurement pasted, or explicit `N/A — not a hot path` |
| **C-08** | No sibling-repo path in imports, tsconfig `paths`, bundler aliases, or build scripts; cross-repo sharing is vendored mirror / published package / codegen | any cross-repo touch | CLAUDE.md §10 | — | `rg '\.\./xood-' */tsconfig*.json */vite.config.*` is empty |

Adding an ID: append a row, never insert; give it a lens file or a CLAUDE.md section as its source; wire the tag into `/proposal` step 7 and the dimension into `osf-verify` the same day, or the row is aspiration, not constitution.
